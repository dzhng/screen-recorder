# Moving reference-parity audit

This directory retains the unresolved moving transition comparison required by
slices 27–29. The three reference PNGs are generated by
`packages/test-harness/editing/transition-reference-parity.mjs` from the
hash-pinned alpha/mirror ProRes sources in `specs/done/ffmpeg-parity`. The
oracle decodes RGBA with FFmpeg, applies the declared opposing-opacity
crossfade in linear-light sRGB over black, and encodes the expected 64×48 PNG.
It does not import the production compositor.

The native candidate frames are the existing moving receipt. The candidate and
oracle agree on the window-bounded identity behavior; strict zero-difference
comparison remains open because one-code-value rounding differences affect up
to 21.68% of pixels (maximum MAE 0.0723). The 500ms midpoint is close (MAE
0.0114). This is a durable failure record, not a visual acceptance or a
tolerance calibration.

A focused native probe also rebuilt the worker with Core Image `RGBAf` working
surfaces. It produced byte-identical moving PNGs and the same mismatch metrics
as the retained `RGBAh` candidate, so the production working format remains
unchanged. The probe receipt is [rgba-working-format-probe.json](rgba-working-format-probe.json);
it records the worker and candidate hashes and keeps this gate open rather than
recalibrating its tolerance.

A second probe rebuilt the worker with an `sRGB` working color space instead of
`extendedLinearSRGB`. That materially worsened all three moving comparisons
(MAE 3.59–4.88, maximum channel delta 73–74), so the production color space is
also unchanged. The result is retained in
[srgb-working-space-probe.json](srgb-working-space-probe.json); the strict gate
remains open.

A third probe asked `createCGImage` for explicit RGBA8 sRGB output before PNG
encoding. Its decoded RGB was byte-identical to the retained production
candidate, so PNG output color-space selection is not the cause either. The
[output probe](png-output-colorspace-probe.json) keeps that result with the
other bounded refusals.

Replay the immutable receipt with:

```sh
node packages/test-harness/editing/transition-reference-parity.mjs replay \
  specs/video-editing-feedback/assets/27-29-transitions/reference-parity/report.json
```

The focused test also verifies source, reference and candidate hashes and
refuses a report edited from `open` to `passed`.
