# 09 — Prove the installed product and publish normally

Unlock: assembled app/CLI updating preserves a populated library and accepted work,
with measured failure limits. Depends on 01–08; this is integration evidence,
not a tester rollout or additional release approval process.

## Seam and artifact

Use a disposable installed A/B pair and a populated same-format library built
through existing fixture owners. Include recording/acquisition/project/revision,
job/results and export facts; record original-media digests before replacement.
No user library is opened. Reuse existing media/results and barrier fixtures.

Choose and commit the final release version before creating acceptance candidates.
Freeze the source commit and artifact identities; do not bump after acceptance.

Human artifact: a compact acceptance report binding A/B revisions, release receipts,
feed/archive hashes, launcher bytes, OS/arch, initial library manifest, complete gate
trace, final runtime identities/health and before/after media/catalog observations.
Point each claim to its narrow earlier proof and named rerun trigger.

## Acceptance

- Explicit manual bootstrap from an old release installs the coordinated launcher
  and updater-bearing app with truthful macOS approval and backup guidance.
- Automatic same-format A→B updates app/service/workers/Node/actual CLI together;
  existing launcher bytes still work. Relocated/default/override paths behave.
- Download while real fixture work is busy; no replacement until it completes.
  Cover queued/running/cleanup jobs, model work, native countdown/start/finalization,
  chooser/publication/deletion, packages and delivery/preview resources using prior
  barrier cases. New arrivals at commitment cannot dispatch; waiting admits work.
- Populated catalog data remains usable and original bytes unchanged. Missing/
  incompatible authenticated format metadata never reaches replacement.
- Off persists, prevents automatic work, and disarms an already-staged update on
  later quit. Relaunch starts no capture or speech-model acquisition.
- Failed feed/archive authentication, download, clean preparation and controlled
  swap preserve/reopen a usable installation where recovery is reversible. A
  stalled post-EOF child prevents swap and reports service unavailability until
  proven exit/recovery; do not claim the closed service reopened. Test final signing.
- New-app startup failure is actionable; demonstrate manual reinstall of a specific
  previous same-format release. Promise neither arbitrary downgrade nor automatic
  postlaunch rollback. Do not repeat a startup failure in an endless hidden loop.
- Reuse prior permission continuity, explicitly accepted by the user on 2026-10-04.
  Do not repeat recipient account/VM, TCC or Gatekeeper proof for this feature.
- Resolve intended GitHub HTTPS latest stable feed/archive paths after publication;
  a controlled local feed is not this evidence.

Keep existing operation, shutdown, source-preservation and agent-isolation contracts
green. Run required full repository checks **once**, when implementation is complete;
[AGENTS.md](../../../AGENTS.md) governs. Start long runs in the background with
visible progress and a stop point. Use prior proofs rather than re-running native
record/render/model work for unchanged facts. Full final Docker skill evals use
slice 08's final-revision matrix; they certify no native updater behavior.

## Closeout and freedoms

Run [review](../../../.agents/skills/review/SKILL.md), required independent Codex
review and documentation reconciliation. Remove transitional production probe
seams; retain frozen research with its limits. Update manual recovery/onboarding
and evidence status before claiming completion. Push the verified source to main,
create the matching annotated tag at that exact accepted source commit, and let the
existing workflow publish verified assets. Evidence-only follow-up commits may
follow; any source/version change requires the affected acceptance to rerun. No extra feedback gate. Confirm published artifact/redirect
readiness, then [close-spec](../../../.agents/skills/close-spec/SKILL.md).

Delegated: report layout and fixture identities, not release scope or acceptance
requirements. Visual shots, if produced, inherit compare/preview review and require
unprimed screenshot-critique as the last visual acceptance check. Human feedback
changes this slice if observed failure/reapproval differs from documented recovery;
record pass, failure and unverified scope honestly rather than waive a requirement.
