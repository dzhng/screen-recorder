# Fresh source-index skill use

A fresh Luna agent received only the product skill, public CLI path/socket, an
asset/stream task and a scratch output directory. It was asked to recover a
canceled inspection, supply a complete source storyboard/coverage and save each
selected image. It did not receive expected rows or implementation access.

The scratch service used the current Catalog 10 project service and frozen
`native-source-picture-v2` worker. Setup imported the canonical two-track fixture
and canceled its actual scene job while the native reply was held. The agent
observed that failure, inspected the dependency, explicitly retried the same index
selection and obtained the ready generation through public commands.

[Unedited result](result/README.md) and retained receipts show all four entries,
all five coverage intervals and four delivered PNGs. Independent grading checked
complete terminal cursors, the requested/decoded clocks, the exact 400–600ms
support gap, ordered successful images and consistent generation. The report
correctly distinguishes sampled evidence, the unproven boundary and source versus
project meaning. This case fits on one page; public journey tests separately
exercise continuation. It does not test every skill branch or establish listening.

The prompt accidentally concatenated the word “asset” with the hash. The agent
recovered the proper opaque ID using public asset discovery; that initial rejected
lookup is retained rather than treated as an engine defect. No source, project,
recording or private database was edited. The scratch service was stopped after
grading. [Manifest](manifest.json) freezes outputs; [setup trace](setup-trace.json)
records actual preparation/cancellation. The first setup script failed before the
scene step due to its own mistaken asset receipt shape; the isolated setup was
corrected before the blind agent ran and is not counted as an agent attempt.
