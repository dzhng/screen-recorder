### Demonstrate fresh execution authority by moving a scratch asset

When prepared admission queues five clip occurrences, the test keeps the queue's
existing execution barrier closed. Two clips select different streams from the
same second asset. The test then moves that asset's scratch file and updates its
catalog filename before starting the queue. Execution must supply both streams
with the new path while preserving the full original recipe. A cache retained
from admission would supply the old path and fail this value assertion.

The task required fresh window authority, real catalog work observations and
complete renderer input values, but did not prescribe how to demonstrate file
authority between admission and execution. The test uses real scratch files and
the existing catalog/queue seams; its declared two-stream probe describes logical
input identities without requiring native decoding. This enables inexpensive
coverage of path freshness and distinct streams without a production hook or
large fixture. Verdict: sound. Confidence: high.
