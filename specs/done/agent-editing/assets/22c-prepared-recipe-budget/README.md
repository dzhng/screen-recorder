# Complete prepared recipes

Prepared recipes live in inventory-bound resource members. They share the project
JSON admission budget with history and other resources; the compact manifest limit
does not constrain an individual execution graph. UTF-8 bytes are counted, and the
aggregate budget and exact recipe validation remain enforced.

The core regression first fails at the old 2 MiB limit with a genuinely compiled
4,001-clip recipe, then preserves the complete string. The public native journey
splits one second into 4,000 sample-aligned occurrences. It preserves three complete
recipes through export/open/adopt, including historical unit-rate/gain output and
current learned-filter output. All prepared PCM and late samples match exactly
after removing the donor and archive with processing unavailable on the receiver.
Cancellation/retry, missing/tampered PCM and original recipe identities retain
their existing checks. This proves metadata scale on short media; it does not
claim the full two-hour package gate or listening acceptance.

Run the existing journey with `SCREENREC_PREPARED_OCCURRENCES=4000` and a native
worker supporting the recorded RNNoise policy. Its default remains the original
single-occurrence journey. [verification.json](verification.json) summarizes the
retained native results. The compressed complete report and package retain the
full recipes and all public traces. Early compact size entries in the report
duplicate values later authenticated by its complete recipe entries; the final
harness omits those redundant entries without changing its checks.

Independent review found no actionable defects and separately passed all prepared
audio tests. The root ran the actual native package journey and aggregate-package
negative controls. No new product endpoint, storage owner, policy or format was
introduced.
