# Follow-pitch learned movie delivery

The public movie consumer preserves the independently verified follow-pitch
retiming and learned noise-reduction result. Lossless preparation is an upstream
prerequisite; it cannot alone establish what the encoded movie contains.

The [verification](verification.json) covers full and ranged previews through the
existing balanced encoding settings. The independent expected PCM is placed in a
plain unit-rate project and encoded with the same settings and selection. Complete
decoded AAC agrees byte for byte. The dry-audio control differs; deliberately
substituting it for the expected learned result fails the assertion. This compares
matched lossy outputs and does not equate AAC with lossless PCM.

The full export is byte-identical to its public preview. Range selection belongs
to preview inspection; the existing export contract exports the full pinned
revision. Complete decoded video in full/range previews equals the fresh dry
composition. The full video's RGB bytes also equal the frozen accepted14e output.
The blue PROJECT badge and repeated slowed counters are authored fixture content.

[Full preview](follow-full-preview.mp4) and [range preview](follow-range-preview.mp4)
retain the exact tested movies. The archive contains public requests/replies,
compiled plans, matched reference movies, dry controls and complete temporal
contact sheets with counter enlargements. The shared test helper owns matched
AAC comparison for both follow and preserve-pitch cohorts; the affected
preserve-pitch cohort remains unchanged.

Root and independent code review found no unresolved issue after replacing a
floating duration calculation with the existing exact rational owner. The
configured Codex CLI model was unavailable, so no CLI review success is inferred.
Listening, speech/spatial quality, other material and physical synchronization
keep their separate gates. No new processor, model, product operation or playback
was introduced by this verification.
