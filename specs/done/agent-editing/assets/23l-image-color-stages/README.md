# One-image composition stage comparison

This supplement asks where the existing composition path changes a fixed valid
PNG: direct FrameImage publication, the same compiled identity graph published
directly, or that graph through its Rec.709 BGRA terminal buffer before publication.
It introduces no production renderer, identity bypass, correction lookup or pixel
tolerance. The source graph, publication owners and complete request remain the
comparison authorities.

The standalone observer delegates the original Core Image implementations and
restores them before each observation is accepted. Exact method encodings and
boundary counts qualify the observation; an unsupported boundary ends the attempt.
The graph is a lazy CIImage. Its declared half-float context is observable, but
private half-float framebuffer samples are unavailable and must not be inferred
from later pixels.

The input was selected from the retained direct-source receipt before new outputs.
Its dimension, profile, sample identity and complete bytes are fixed. Retargeting
that already published PNG into the saved single-layer graph removes movie decode
from this diagnostic. It therefore cannot prove equality of the missing historical
decoder buffers or establish the historical video difference's cause.

[The failed compile record](compile-failure.json) retains the original executed
source, compiler error and terminal evidence. The failure happened before any
image or pixel-reader dispatch. Its SDK spelling correction changes only the
color-space type identifier's imported property name; the original attempt remains
immutable. Runtime authority and the separately authorized successor are retained separately.

The compiled objects match the frozen linked-code pins; current module files and
toolchain/SDK are independently pinned. Matching source/object authority is not a
claim that this separately linked diagnostic equals the historical worker binary.
Original material, workers, modules and evidence packets remain untouched.

[Compact results](results.json) point to the complete archived comparison and show the direct and compiled-graph direct publications
preserve every normalized RGBA byte for this image. The terminal-buffer route changes
RGB samples by one value while preserving alpha. The change is present in the
retained pre-encode provider rows, before PNG encoding; every provider's active
rows equal its own normalized PNG samples. Provider bytes beyond the declared
image rows remain retained separately from active-pixel comparisons.

Both actual contexts report the same extended-linear-sRGB half-float working
representation. A difference in their declared working format or color space is
therefore not established here. The observed distinction is the route through
the tagged Rec.709 BGRA terminal and its subsequent publication, without isolating
which internal conversion or rounding step changes values.

[Verification](verification.json) binds all complete samples, encoded images,
metadata, executing source/binary, commands and actual child terminals. Exact
duplicate payloads share lossless tar storage. The failed compile archive is
unchanged. The successor performed one image diagnostic, followed by the four
existing pixel-reader commands; no retry, service operation or worker/module
rebuild ran. Its observations pass their ABI, delegation, count and restoration
guards. No process-failure or unsupported-ABI branch is claimed exercised.

The next supported production seam is still-picture publication of the existing
compiled graph, sharing graph construction with the movie terminal owner. That
correction requires its own implementation and affected-contract verification.
This diagnostic supplies a concrete reason to investigate it; it does not authorize
an identity-only bypass, alter movie output, close the original paired-frame
preservation gate or adopt a tolerance.

Root [merged verification](merged.json) checks both immutable packets and rederives
the complete saved pixel differences without another diagnostic execution.
