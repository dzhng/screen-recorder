# Preparation review

Shape: one maintained acceptance entry point, a fixture-input binding helper and
focused tests. It composes existing public owners and the shared JourneyService;
it adds no production type, queue, cache, table, model recipe or media treatment.
The file identity helper consumes the core's bounded descriptor hash owner rather
than introducing another hashing engine. Source selection and clock checks belong
to the fixture boundary, where a mismatched original would invalidate the marks.

Diff: API response nesting defects discovered during real admission were corrected
to public project metadata and revision wrappers. Their failed complete replies
remain retained. Resume preserves exact request IDs and the isolated home, worker
and brief, and verifies the project remains unedited. It rehashes personal originals
without modifying them. Archive extraction uses one named bounded member and a
scratch output, never archive-provided output paths. Full source support rows are
consumed through public pagination; a gap cannot masquerade as physical coverage.
Machine bindings name original-media and asset-relative ranges separately so a
caller cannot mistake one for the other.

Docs: the leaf and evidence state preparation-only scope and identify the exact
next acceptance step. They make no transcript, listening, visual or synchronization
claim. The consumer screenrec skill is not invoked. Root hub/global choices remain
owned by the parent lane. Local links are checked. This pass includes no configured
CLI-review retry, Claude call, UI or installed switch.

Tests pin source-byte/clock refusal, known human mark projection and gap refusal.
The initial missing-module test is retained red before implementation; real public
cohorts validate actual immutable admissions and exact replay/reopen behavior.
No latency threshold or existing deadline is changed under host contention.
