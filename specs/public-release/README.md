# Public distribution proposal

Status: future proposal. [Versioned GitHub releases](../../scripts/README.md) already
own package delivery; broader public support, onboarding and updates remain separate
questions. [Tester distribution](../tester-release/README.md) informs that work.

When activated, inspect the released package, accepted limits and actual user
feedback. Define the supported audience and workflow before selecting an updater,
service or distribution mechanism. A public package does not imply accounts,
telemetry, hosted recordings, remote MCP or automatic data migration.

Signing/notarization, update recovery, compatibility commitments, support, pricing
and dependency/model redistribution need explicit decisions. Privacy guidance must
match the existing [product boundary](../../README.md#product-boundary) and actual
local processing, not an inferred hosted product.

Acceptance concerns a new user finding, installing, using and safely updating the
supported workflow. Preserve originals and chosen library policy through those
steps. Documented recovery and support must agree with delivered behavior; package
CI alone cannot establish that experience.
