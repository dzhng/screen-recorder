# Planning decisions and synthesis

The user decisions live in [MAP](MAP.md); [contracts](contracts.md) is the
implementation authority. This record explains choices made while turning the
brief into slices. Proposals here do not override those files.

## Independent drafts

Three fresh, independent whole-plan drafts received the same discovery brief and
inspected the code without seeing another draft. One Codex subagent optimized
for fewest slices; two read-only `claude -p --model opus --effort high` sessions
optimized for risk-first ordering and seam quality. The collaboration tool's
session limit prevented another in-process agent, so Claude CLI sessions supplied
the other independent passes. No drafter modified the repository or ran media
experiments. All three complete drafts were read before synthesis.

| Agreement or disagreement | Canonical choice and reason |
| --- | --- |
| All drafts reject extending anonymous ordered spans into general composition. | A pure composition package owns identity, time and edits; source acquisition evidence survives separately. |
| Fewest-slices draft bundles assets, store, native rendering, preview, export and packaging into its first slice. | Preserve its early useful checkpoint, but split those seams into 00–09 and portability into 22. Each next implementation step has one contract and a decisive artifact. |
| Risk-first draft starts renderer/stretch/voice/camera reproductions early. | Adopt early research branches so failure is found before expensive integration; add a separate speech-evidence reproduction because omitted fillers already have evidence. |

| Drafts suggest either a new core module or a pure package. | Use `packages/composition` for a testable I/O-free algebra shared by protocol/service/harness; keep persistence/jobs/assets in the existing core/service. |

## Architectural judgments

- Immutable admitted assets and dependency retention come before composition
  features. Portable packaging arrives later but cannot require retrofitting
  ownership. A moved external file or deleted donor project must not break edits.
- A fresh library directory avoids implicit history/schema migration while keeping
  one new writable catalog. Old media/catalog remain available for explicit media
  import; old jobs and revision histories are not replayed by the new app.
- Asset preparation, synthesis and stretching happen outside edit commits. A
  batch only references ready inputs; a failed preparation cannot half-edit a
  project. Generated bytes, not just seeds, are retained.
- Constant-rate clip mappings plus split/retime primitives cover the accepted
  workflow. Reverse and continuous speed ramps are not silently promised. Ordinary
  keyframes remain general for spatial/opacity/gain animation.
- Clip-source anchors follow moving footage; normalized clip anchors cover held
  frames/stills; explicit project anchors remain fixed. One resolver handles all
  three. Ripple only moves roots, then resolves descendants once.
- Linked operations share project-time ranges and preserve relative timing. A
  ripple scope omitting an affected linked track is rejected; selected-scope edits
  explicitly split/unlink. No ambiguous "expand or reject" choice remains.
- Cubic splits preserve the whole function through restriction/reparameterization,
  not only a sampled boundary value. This is required for invisible splits.
- Baseline native input/output profiles and measured resource budgets are planning
  choices, not user mandates or measurements. The slices validate them and record
  necessary changes without silently dropping user capabilities.

## Recursive splitting and final review

The broad initial-composition rung was split into identity/time, admission, reducer,
transactions, compiler, native reproduction, video execution, audio mixing and
public preview/export. Visual work separates static geometry, motion and text.
Speech quality reproduction (12) and production adoption (12b) are separate so a
new ASR/alignment choice cannot slip into a generic inspection pass. Voice and
stretch each have reproduction then parity-controlled integration. Camera has a
physical clock proof before capture integration. Cutover, scale and full agent
acceptance have distinct verdicts.

The read-only contract review identified and corrected missing sync-offset rules,
held-content anchors, double-ripple risk for attached overlays, incomplete cubic
split semantics, and missing export recovery/package-admission operations.
Further final review findings belong here with their disposition before closeout.

The final ownership audit found that project phrase search needed a rule for
simultaneous speech tracks and cross-clip adjacency. Contracts now search each
track independently and define gap/partial-word behavior. It also found that
project-evidence frame integration needed the public renderer checkpoint;
slice 10 now depends on 09 and retains rendered-frame delivery in that owner.
Camera integration similarly depends on 09 for its post-capture replacement check.
Package development is independent of unfinished synthesis/camera producers;
explicit metadata fixtures prove dependency closure, and final acceptance uses
real outputs. All findings were resolved; no compatibility or cycle defect remained.

No production code, model weights, captured footage or runtime performance results
were generated in this planning pass. The existing CLI skill is from discovery.

## Ordered processing amendment

The user explicitly chose one get/set stack per clip, track, nested group or
output, processing that target's combined result. This supersedes earlier
clip-only/source-stage drafts and the briefly accepted inherited-member-settings
proposal. Compatible processing survives replacement; media/caption attachments
retain their distinct lifecycle. No migration or UI scope was added.

Four independent read-only drafts informed this amendment: Codex fewest-slices,
risk-first and seam-quality lenses, plus Claude Opus's simplicity/end-to-end lens.
All agreed on typed target ownership, a single parent tree, preserved originals,
explicit gain and backend quality gates. Synthesis chose one canonical collection
of target-owned stacks rather than embedding duplicated schemas on every entity.
It is not an attachment store: replacement/partitioning explicitly owns its lifecycle.

The fixed clip stack follows retiming, matching the result-oriented rule at every
target. Claude proposed pre-retime clip processing to give denoising natural-speed
speech; this remains a rejected alternative because it gives clip and parent
stacks different timing behavior. Post-retime denoise is an explicit research gate,
not an assumed quality success. No hidden upstream movement is permitted.

Homogeneous audio/video groups use fixed transparent project-canvas intermediates,
not content-derived bounds. This keeps parent coordinates stable when children
change. Output has one list with media-typed steps, rather than two master APIs.
Nested routing does not imply group-local time or a new synchronization policy.

Atomic rejection of incompatible retained processing was chosen over editable
but unrenderable revisions. Errors name the settings needing repair; an earlier
set/reset in the same batch can resolve them. This preserves existing reducer
validation and prevents silent bypass or loss of configuration.

The foundation is split into 03b topology and 03c stateless lifecycle so the next
pass has one verdict. Existing audio/video/curve slices own real execution; 12c
reproduces denoise and 15a adopts it after retime/window support. Additional IIR,
blur and color-matrix families proposed by Claude are not added just to test a
framework. Its claim that copying clip fields alone preserves split processing
was not adopted: identities, curve restriction and DSP state need explicit gates.
Universal finite-context assumptions and clip-only fallback denoising were also
rejected; research must prove context at the required scopes before readiness.
