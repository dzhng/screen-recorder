# Public project audio tap journey

[The journey](../../../../packages/test-harness/editing/audio-taps.mjs) authors a
nested project over actual publicly admitted stereo WAV and video assets. Both CLI
file streaming and MCP inline audio deliver each tap, and every decoded float32
sample is compared against the named modular stereo signal and an independent gain
oracle. Non-unity completed stacks make accidental child bypass visible; inspecting
a child excludes its parents. WAV headers are verified independently of JSON receipts.

[The passing report](./report.json) records all 15 tap combinations through both
transports, full/range sample parity at a non-sample-aligned origin, explicit existing
step reordering/settings/bypass, and historical bytes after head advancement and
service restart. A real native reply barrier proves cancellation discards an already
rendered result and explicit retry delivers correct PCM. Public project deletion
retires the project while the imported source remains available.

This runs real asset probing, production service/queue/cache/renderer, native mixing,
and public authoring/delivery. It uses no database seeding or fabricated worker
responses. The deterministic source fixture is generated by the harness. Native and
source hashes are in the report; [runtime hashes](./runtime.json) and [package manifests](./package-manifests.json) identify the frozen
built files. The runtime was copied from the root's successful project audio route
build. No copied runtime or production sources belong to this harness commit.

Two independent mutations establish sensitivity: [removing audio dispatch](./dispatch-mutation.json)
fails the public request; [bypassing the completed clip stack](./clip-bypass-mutation.json)
fails exact PCM. All frozen runtime file hashes match after restoration. Local
[format controls](./format-controls.txt) reject mislabeled integer, rate, channel and
alignment headers while accepting the unchanged float WAV.

[Review](./review.txt) found and resolved a unity-gain blind spot, missing WAV format
validation and failure cleanup/reporting defects. The final full journey passed after
those fixes. Output media remains in the directory recorded by the [run receipt](./run.txt) and can be regenerated;
this evidence is numerical conformance, not a listening-quality verdict.

The real video coexistence case is covered. An unavailable video processor cannot
currently be authored: the registry exposes only audio gain. That future processor
case remains pending rather than being manufactured. This journey does not prove
outstanding-lease deletion, source capture masks, excluded-source poison or large-WAV
memory; their separate named gates still apply before closing 11a.

[The wired-render integration rerun](./wired-render/README.md) preserves the same
public WAV bytes after adopting locked audio attempts.
