# Public source picture delivery

The selected-source journey exercises the real service, native worker, CLI file
delivery and MCP image delivery in an isolated home. Its source selectors come
from public imports. Source time is relative to the selected stream origin;
physical sample provenance remains in the container clock. Missing source
pictures remain unavailable and never acquire a black replacement image.

[The executable journey](../../../../packages/test-harness/editing/source-frame-evidence.mjs)
owns the assertions. The retained report records both selected tracks, nonzero
origin, physical gaps, bounded delivery, mixed ordered batches, canceled native
work followed by explicit retry, and unchanged input hashes. Actual acquisition
import retains the video binding; a fresh uncached request still renders after
removing the donor directory and restarting the service. No models, capture,
playback, user library or user home are used.

`public.json` retains the passing receipts and exact color-managed RGBA hashes;
`images/` retains delivered CLI PNGs. MCP inline bytes match those files. Each
public picture matches an independently reviewed source reference, or the reviewed
bounded native image, exactly after applying its embedded profile into sRGB.
This establishes preservation of the earlier limited visual acceptance, not a
new visual judgment or broad codec/color fidelity claim.

The first actual public run failed because an absent acquisition property was
serialized as explicit undefined. The parent-owned source planning and batch
routes now omit absent properties. `first-red.json`, `service-first.txt` and the
two runtime manifests preserve that boundary; the corrected frozen runtime passes.
The native worker is pinned by the runtime evidence and remains unchanged.

The independent review exposed an ICC-blind RGB oracle, incomplete MCP absence
checks and cleanup that could be skipped by evidence-write failure. The harness converts profiles into common sRGB RGBA, inspects full MCP content and
unconditionally removes its scratch home. A subsequent review also required
image dimensions to match both reference and published receipt, and MCP batch
items to preserve timestamp ordering and full sample provenance. Swapped dimensions
and swapped successful batch items each fail their focused negative control. A wrong-track public run fails the
reference oracle. A linear-sRGB retag would pass the former RGB-only comparison
but fails color-managed equality; partial transparency fails opacity admission.
An injected evidence-write failure leaves no scratch home. These controls are
retained beside the green report; traces use ordered run-length encoding with
original report hashes.

The public acquisition importer admits physical video support, not a custom
video exclusion mask. Narrower video-mask checks remain native/core evidence;
this journey does not invent public admission by editing storage. The [acquisition-picture journey](../10d-acquisition-pictures/README.md) reconciles
10d project-gap acceptance through public audio-context anchors; it does not add
a direct-source video-mask producer. Raw still-image admission,
source scene/cut/interruption index generalization, and broader visual fidelity
remain pending under 10d/06. Existing project frame acceptance is a separate gate.
