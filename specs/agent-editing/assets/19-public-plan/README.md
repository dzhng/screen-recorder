# Public voice integration plan synthesis

Independent [fewest-slices](minimal.md), [seam-quality](seams.md) and
[risk-first Claude](risk.md) drafts examined the same brief and real code without
reading each other. These are planning evidence; their proposals are not the
canonical API. The owning slices19c–19f and parent19 are authoritative.

Keep four seams: common preparation, measured settings, retained audio excerpts,
and durable public generation. Preparation and settings work can proceed
independently after their prerequisites. Parent19 retains complete contextual
editing, listening and performance acceptance; do not duplicate it as another
acceptance slice or close it when jobs succeed.

Use generic retained audio excerpts rather than a voice enrollment/reference
registry. Pair the selected reference and explicit transcript in the frozen
generation request. Same bytes with different text are different requests;
multiple extraction origins must not be silently collapsed into a chosen origin.
Canonical references pass through unchanged. Native extraction from the original
take is not promised to reproduce the ffmpeg-made frozen reference: compare the
frozen imported reference exactly and judge newly extracted material separately.

Common preparation first supports explicit local admission of a verified runtime
artifact, with existing pinned model file acquisition. Relocation is not proof of
upstream distribution or rebuilding from wheels. Preserve ASR through one owner,
with bounded asynchronous runtime verification. Do not publish arbitrary source
paths as readiness or instantiate multiple owners of the shared staging folder.

Reject the risk draft's preset-only public intermediate: agents need supported
settings before public generation is accepted. Preserve requested1.05 and effective
1.5 in the frozen fixture rather than silently rewriting its recipe. Measure
termination: a token-bound cutoff cannot be indistinguishable from completed
speech. Streaming is a distinct synthesis algorithm; no streaming transport
subsystem is required by this plan. Its support/absence must be explicit in
capabilities and must not be advertised as equivalent output without evidence.

Do not remove worker verification merely because preparation once succeeded;
consolidate identity ownership while preserving detection of changed inputs at
execution. Likewise, do not retain whole donor asset graphs merely to explain an
excerpt. Retain the excerpt and historical provenance; generated assets retain
actual reference bytes through the existing dependency owner.

No new request-ID table is planned: existing queue deduplication keys exact frozen
inputs by target/artifact/input identity. Verify lost-response replay through that
contract. Add a separate request-ID mechanism only if a concrete required semantic
cannot be represented by that owner, after updating this plan.
