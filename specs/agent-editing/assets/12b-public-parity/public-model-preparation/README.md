# Public selected-model preparation

The actual CLI/MCP routes initiate preparation through the production service and
`Models` owner in a fresh isolated library. The external fetch edge serves the
unchanged, verified registered model bytes. A held fetch makes preparing observable;
an intentional HTTP 503 establishes truthful failure and retry. This is transport
and preparation verification, not live Hub availability or fresh inference.

[The report](report.json) retains every complete public request/reply.
[Verification](verification.json) binds the execution to the prior model-readiness
source/runtime archive: every inherited pin still matches the root checkout.
[The manifest](manifest.json) pins the checkpoint programs, external-boundary
logs, production receipt and before/after original-file identities in the archive.
Ready preparation is idempotent, ready state survives service reopen, and original
personal models remain unchanged. The successful scratch library was removed
after service shutdown; the evidence remains.

Together with the retained actual inference and protected-media public parity,
this completes selected-baseline adoption in 12b. It supplies no new speech-quality,
listening, physical capture, latency or installed-release verdict. The selected
recipe and its known best-effort limits remain unchanged.
