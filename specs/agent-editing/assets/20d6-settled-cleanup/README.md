# Settled recording cleanup

The explicit recording cleanup command runs through the existing recording-owned
queue target and directory lifetime. Native publication code alone proves and
removes working members. It never republishes media or changes capture lifecycle.
A ready result distinguishes removed, already clear and retained roles. Missing
proof or a missing journal retains bytes; identity conflicts are final. Positive
access/IO or ownership failures can be explicitly retried.

The retained public journeys use actual prerecorded controller output. Working
attempts are reconstructed from its exact receipt intent and candidate/prepared
hardlinks, which recreates a publication-before-cleanup boundary without claiming
an actual machine crash. A real read-only attempt directory fails cleanup while
the independent system role is removed. Restoring permissions and retrying the
same job after service restart removes the remaining owned work. Repeated requests
join that job. Complete recording state, canonical/journal byte hashes and the
published source-evidence result remain unchanged.

A separate journal owner produces public retryable CAPTURE_BUSY; releasing it
allows the same job to finish. Fragmented-source cancellation and deletion tests
wait until the native journal lease is actually observed. Cancellation preserves
saved media; deletion drains the worker and removes the recording. The deletion
fixture initially used755 directories, corrected to production0700 permissions;
that setup refusal is retained and is not a product defect.

Native publication tests cover exact outcomes, both accepted/committed mismatch
directions, no-proof retention, missing journal, wrong source, symlink proof,
unknown members, permission recovery and unchanged canonical availability. The
service typecheck and15 focused service tests pass. Final independent review found
no actionable regressions; its native behavior assessment was read-only. Earlier
review sandbox socket/Swift restrictions are not presented as runtime passes.

[verification.json](verification.json) identifies the scoped gates. Compressed
scripts and reports preserve original scratch paths. `prerecorded-source.tar.xz`
retains the short input; the fragmented input comes from the existing
[controller evidence](../20d-activation/README.md). The artifact manifest
hashes every retained member. This checkpoint does not close terminal diagnostic
message disclosure, physical camera acceptance or installed-app cutover.
