# Registered voice settings adoption

The registered execution profile exposes supported controls and reports both
requested values and effective clamp/filter modes. Its bounds come from the
retained resource experiments; they describe measured work, not universal model
capacity or voice quality. The pure durable receipt schema does not import the
active profile. Durable metadata is strict so parsing cannot silently discard
identity fields; worker response decoding tolerates additive fields explicitly.

The runtime carries the reviewed single-helper probability repair. Valid filtered
results and the default bypass remain unchanged. An empty result is repaired only
when the input has finite support and no NaN or positive infinity; the first
maximum-logit candidate is restored. No larger top-p minimum was fitted. Zero and
one preserve disabled-filter behavior, and every positive binary64 value below
one remains admitted. Invalid model logits are not rescued or newly refused.

[Results](report.json) retain the exact registered identities and receipts. The
final public preparation gate passes its unchanged180s deadline, donor/network
closure, restart/readiness and mutation controls. The25 entry checks pass exact
frozen word/phrase WAV and PCM parity, token-budget refusal versus EOS, changed-seed
replay, actual reference/token admission and the original lifecycle limits.
The earlier filtered sample is read from its retained archive: both fresh new
worker runs match its complete WAV bytes. The smallest positive top-p completes
finite audio with EOS. Actual managed-runtime sampler probes repair all62 retained
empty distributions and preserve the217 previously valid selected tokens; the
more detailed zero-tolerance logits/RNG proof lives in
[19d1](../19d1-probability-filter/README.md).

The final cancellation check reaches staged output in2.666s, then returns after
10.735ms with the child closed and workspace empty. The deadline check retains its
10s worker limit. These are scoped observations, not a cold-cache or concurrent-load
latency guarantee. No automatic playback or new listening acceptance occurred.

The archive also retains failures rather than replacing their verdicts:

- An earlier180s preparation timeout and8s staging-observation failure remain
  unattributed. A separately labeled600s diagnostic obtained a verified receipt
  in100.711s; it did not change the acceptance gate. Final gates use original limits.
- The unsupported-rate test inherited an input/output filename collision, so its
  former error expectation never reached rate validation. Separate output paths
  now exercise the actual typed reference refusal.
- Isolated lifecycle diagnostics first omitted the workspace, then created it
  with0755 instead of the required0700. Those setup failures are distinct from
  the original timing red. Corrected diagnostics and the final real harness pass.
- Independent review found signed-zero request/receipt inequality; normalization
  fixes it. A later regex claim was rejected after Node/Zod tests demonstrated
  that non-multiline anchors refuse trailing line terminators.
