# Project storyboard candidates

This is pure selection evidence, not published screenshot-index acceptance.
The [selector](../../../../packages/core/src/project-index-selection.ts) receives a
validated composition and its existing compiler-selected video processing plan.
Scene reads use inverse available-fragment windows from the occurrence owner;
constant stacks add no separate temporal interpretation. Empty target validation,
retained publication, coverage receipts, deletion and public delivery remain later
10d gates.

The [behavior tests](../../../../packages/core/src/project-index-selection.test.ts)
exercise actual compiler timing and occurrence projection with retained-scene-shaped
fixtures. They cover observed scene sides, fractional retiming, repeated footage,
overlapping layers and scoped taps, support gaps, holds, empty/audio-only output,
source stillness, deduplication, cancellation and explicit overload refusal.

[Verification](verification.json) records the executed checks. The
[direction negative control](direction-mutant.txt) changes only scene-side
quantization: both selected samples then show the earlier picture at 333,333
microseconds and the old/new test fails. Restoring production selection passes.
No native worker, app launch, speaker playback or live user library was used.

The selection buffer and evidence walk have explicit limits with structured
revision/limit diagnostics. Iteration yields and checks cancellation, including
a no-progress source-reader control. These are pathological-work safeguards, not
release-scale latency or memory measurements; slice 24 retains that acceptance.

Direct picture requests currently clip their receipt visibility to the requested
one-microsecond window. Later materialization must validate frame identity and
use the compiler's complete frame visibility for sampled coverage, without
claiming any unrendered interval as equal.

Before scheduling any native picture, the materializer must preflight each selected
record through the retained store's existing serialized-row budget. Many reasons
can attach to one frame even when the selector's total count limits are satisfied.
Keep this storage check with the store; test a heavily overlapping frame and prove
structured refusal occurs before rendering, rather than introducing a second byte
policy in the pure selector.
