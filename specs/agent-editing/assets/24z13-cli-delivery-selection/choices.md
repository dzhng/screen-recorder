## Sound

### Reuse one scratch delivery fixture across the three caller controls

When a CLI receives one picture or a batch containing duplicate pictures, the
fixture opens real leases through the existing service delivery owner. The child
writes those supplied bytes to files; the test compares every byte and observes
actual socket requests. The same fixture closes its listener during a read to
exercise a later item after the service disappears. The plan left fixture layout
open. Sharing this setup keeps the controls on the same public caller path and
adds no production hooks or alternate lease implementation. Confidence: high.

### Preserve the batch's existing overall success status on item failures

A batch can be accepted while individual pictures fail. The disappearance fixture
therefore expects CLI exit zero with explicit failed item results, including the
unchanged first truncated-frame error and the later socket connection error.
The task required preserving item isolation/errors but did not restate this exit
policy. Changing the overall status would alter the public batch contract outside
the selection correction. Confidence: high.

### Reference the existing complete runtime archive instead of duplicating it

The new checks compare all owned source/emitted bindings and SDK modules against
the current-preparation authority, retaining the three changed paths plus exact
phase snapshots. The prior archive continues to own unchanged runtime bytes.
The task required compact evidence without prescribing its packaging. This keeps
root verification reproducible without another complete runtime copy.
Confidence: high.
