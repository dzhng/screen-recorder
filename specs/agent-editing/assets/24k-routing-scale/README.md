# Routed long-project inspection and queue behavior

A project with existing stateless stacks previously lost independent placement
batching, making every appended clip revalidate the entire routed document. The
public request timed out after committing once; exact replay preserves that one
revision. A copied prior revision reproduces the cost under CPU profiling. Existing
stateful normalization defines the eligibility boundary, shared with the editor;
this is not a gain-only optimization or a new editor.

The next public gate exposed repeated scans of sources already known to have no
capture or scene evidence. Skipping only those proven-empty sources preserves
coverage, dependency invalidation and measured source rows while allowing ready
editorial cuts to use their existing bounded merge. Neither the page budget nor
any client deadline changes.

The [journey](../../../../packages/test-harness/editing/scale.mjs) compiles all
project edits through CLI/MCP and the actual service, then renders only short late
windows from a one-second authored source. It checks exact complete output bytes,
source request selection, native RSS and public queue behavior. The queue barrier
holds a successful native reply before publication; cancellation of active native
decoding remains a separate existing gate. Repeated queued cancellation drains
staging and does not retire the referenced original asset.

The requested page size is a maximum, not a promise of that many rows in one
response. Measurements follow continuations to obtain exactly 250 actual rows.
Original traces, profile, requests and final reports are retained without replacing
the reds. Observations are machine/load-specific; no 1080p preview, duration-doubling
memory or full-prefix decoder byte measurement is inferred from these short reads.

The absent-source loop performs no source IO and advances within the existing
10,000-occurrence admission bound. Published evidence still uses the scan budget.
Pending scene work prevents readiness; later evidence publication changes pinned
dependencies. A missing file behind a published pointer still takes the ordinary
error path, so absence of publication is not confused with corrupt retained data.
