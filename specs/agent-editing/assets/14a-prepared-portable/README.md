# Portable prepared PCM

Prepared unit-rate and constant-gain output moves through the public package
operations without losing its original recipe, implementation identity or exact
PCM. The [native receipt](report.json.gz) records the worker digest and independent
sample oracles. The [harness](../../../../packages/test-harness/editing/prepared-package.mjs)
seeds the existing core owner explicitly: this is not a public preparation command,
RNNoise/stretch adoption or a speech-quality claim.

After donor/archive removal and receiver restart, current and historical receipts
read their exact samples with the original executor unavailable. A late read reads
only its selected PCM interval, and public asset-audio inspection also delivers
exact requested samples. The copied file receives a receiver-local identity after AssetStore
staging links close. Byte identity, recipe provenance and local filesystem identity
remain separate authorities.

The package resource follows the existing asset/reference graph. Staged validation
compares the retained recipe's composition meaning with its immutable revision,
without substituting current implementation identities. Asset publication, adopted
revision references and queue receipts share one transaction. An adopted ready
receipt does not create a replacement job. Unknown recipes, unresolved execution
requirements, missing upstream references and invalid PCM are refused.

The public journey verifies canceled adoption stays invisible and the same request
can retry. Core negative controls fail when the cancellation fence or exact-ready
read guard is removed. Missing and replaced retained PCM remains a read error.
The first corruption-control attempt hit the immutable asset's write permission;
the corrected control replaces the file and confirms the owner refuses it.

Whole-project recipes use the enclosing package manifest budget. The retained
many-clip regression shows why applying the small publication-input budget would
reject an otherwise valid short project; no graph is truncated to fit it.

The [preservation receipt](preservation-report.json.gz) keeps every existing package
check, including source/project indexes, real transcripts with models absent,
acquisition journals, current/history media, undo, replay and corrupt members.
Independent review found no actionable defect. Its service test could not bind a
socket in its sandbox; the normal service run passes and is recorded separately.

Public preparation/processing consumers, actual 15a output, full scale acceptance,
non-current package export and caption/font dependencies remain their own gates.

Final focused checks pass 80 core tests and 11 service tests; core types and the
CLI/service build pass. One earlier core run timed out in the unchanged queue
history test at its existing five-second deadline. The same test passes from the
baseline checkout, and the complete focused rerun passes without deadline changes;
both the timeout and subsequent results are retained here.

Combined-root confirmation builds the shared packages and passes 104 focused
core/service tests. The [root native journey](root-report.json.gz) repeats every
prepared relocation check with the combined font/output-settings worker. This
confirms integration; it does not broaden the DSP or public-preparation scope.

The root text-aware combined worker also passes every prepared relocation check;
[root confirmation](root-text-combined-report.gz) preserves exact current/history
PCM after the manifest/font dependency changes.
